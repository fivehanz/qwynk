# Qwynk v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **On approval, copy this file to `docs/superpowers/plans/2026-09-10-qwynk-v1.md`** and execute from there (plan mode restricted authoring to `~/.claude/plans/`).

**Goal:** Take Qwynk from spec-plus-scaffold to a working self-hosted link shortener: tightened specs, a stripped dependency tree, an ETS-cached redirect hot path, a privacy-first async analytics pipeline, and a branded LiveView admin.

**Architecture:** Phoenix 1.8 + Ash 3 + PostgreSQL + ETS + LiveView. No Redis, no job queue. `/_/*` is the admin/auth namespace; `/:slug` is the redirect namespace. Redirects serve from an ETS cache holding `link_id` so the analytics path never needs a second lookup. Analytics enrichment (hash, geo, device, referrer domain) happens off the request process and *before* buffering, so raw IP and User-Agent never enter any persistent process state.

**Tech Stack:** Elixir 1.18 / OTP 26, Phoenix 1.8, Ash 3, AshPostgres, AshAuthentication, PostgreSQL 16, Bandit, Tailwind v4 + DaisyUI v5, `mmdb2_decoder`.

## Context

Verified against the repo: 20 commits, working auth (`User` / `Token` / `ApiKey`), a deployed Astro landing page, and **~30 lines of product code** (`SlugGenerator`). `Qwynk.Traffic` and `Qwynk.Analytics` are literally `resources do end`. Every PRD core-logic section (§3.1–3.4) is unimplemented; `deps/` has never been fetched in this checkout.

The review's conclusions were checked and hold. Three additional findings came out of verification:

1. **`ASH.md` §1 line 21 specifies `:301` / `:302` as atoms.** Invalid Elixir — atoms cannot begin with a digit. Resolved below as `:permanent` / `:temporary`.
2. **`picosat_elixir` is the FreeBSD build tax** — it is the C NIF forcing `gmake` + `clang` into the README prerequisites. Ash's own get-started docs sanction `{:simple_sat, "~> 0.1"}` as the pure-Elixir replacement. Swapping it directly serves PRD §5.3 ("standard Mix, no Docker").
3. **`AGENTS.md` line 47 is `<!-- usage-rules-start -->`.** Everything below it is regenerated by `mix usage_rules.sync`. The new architecture rules must land *above* line 47 or they will be silently overwritten.

Approved decisions: full scope through GeoIP and charts; `DailySalt` table kept with a purge rule; `:permanent` / `:temporary` atoms; `simple_sat` swap.

## Global Constraints

- Elixir `~> 1.18`, OTP 26. Must compile on FreeBSD 14 with standard Mix, no Docker, no C NIF (PRD §5.3).
- Redirect hot path budget: **< 5ms internal**. On an ETS hit it must not touch PostgreSQL, must not perform a GeoIP lookup, and must not write analytics synchronously.
- **No raw IP or User-Agent may enter `AnalyticsBuffer` state or any database row.** Privacy boundary is crossed in `Analytics.Enrich`, before buffering.
- No cookies on the redirect path (PRD §5.1).
- No Redis. No background-job framework. No new dependency that a few lines of stdlib covers.
- `config/config.exs` sets `default_actions_require_atomic?: true` — **any update action carrying an `after_action` hook needs `require_atomic? false`** or Ash raises at compile time.
- AGENTS.md forbids external vendor `src`/`href` in layouts; all JS/CSS goes through `assets/js/app.js` and `assets/css/app.css`.
- Commit after every task. Run `mix precommit` before declaring a task done.

- [ ] **Step 1: `AGENTS.md` — insert above line 47 (`<!-- usage-rules-start -->`), never below it**

```markdown
## Qwynk Architecture Rules

1. The redirect path must never synchronously write analytics.
2. The redirect path must never perform a GeoIP lookup on an ETS hit.
3. The redirect path must never require PostgreSQL on an ETS hit.
4. Raw IP and User-Agent must never enter AnalyticsBuffer state or any DB row.
   The privacy boundary is `Qwynk.Analytics.Enrich`, which runs before buffering.
5. AnalyticsBuffer must have a hard memory limit and drop events rather than
   grow without bound. Dropping analytics is always preferable to degrading redirects.
6. ETS cache values must contain `link_id`, so analytics never needs a second lookup.
7. Every Link mutation (update, disable, destroy) must invalidate the ETS entry.
   TTL is a safety net, not the invalidation mechanism.
8. Never introduce Redis without explicit approval.
9. Never introduce a background-job framework for analytics or token cleanup.
10. Preserve FreeBSD compatibility: standard Mix, no Docker, no C NIF dependencies.
```

- [ ] **Step 2: `PRD.md` §3.2 — replace the hot path with the explicit cache contract**

````markdown
### 3.2 The Hot Path (Redirect Flow)
Latency Budget: < 5ms (Internal Processing).

ETS entry shape — `link_id` is present so analytics never re-queries:

```elixir
{slug, %{link_id: uuid, destination: binary, strategy: :permanent | :temporary}, expires_at_ms}
```

1. `GET /{slug}` — response always carries `x-qwynk-cache: hit | miss`.
2. **Layer 1 (Memory):** `:ets.lookup(:qwynk_cache, slug)`.
   * Hit and unexpired: redirect. Dispatch enrichment to `Qwynk.TaskSupervisor`.
3. **Layer 2 (DB):** miss or expired → `Qwynk.Traffic.resolve(slug)`.
   * Found: write ETS (TTL 10m), redirect, dispatch enrichment.
   * Not found: 404 HTML. Nothing is cached and nothing is logged.

`:permanent` → 301, `:temporary` → 302.

**Cache invalidation.** TTL is the fallback, not the mechanism:
`create` → no write (populated lazily on first hit). `update` / `disable` /
`destroy` → delete the ETS entry in an `after_action` hook. Without this, an
edit at 10:02 keeps serving the old destination until ~10:11.
````

- [ ] **Step 3: `PRD.md` §3.4 — replace the analytics pipe.** Enrichment moves *before* buffering, and the buffer becomes bounded:

````markdown
### 3.4 The Analytics Pipe (The "Buffer")
Direct DB writes on the request path are forbidden. So is buffering PII.

```
HTTP request ──► IP, User-Agent, Referrer   (request memory only)
                        │
                        ▼
              Analytics.Enrich  ◄── privacy boundary
                        │
      visitor_hash · country · device · referrer_domain
                        │
                        ▼
                 AnalyticsBuffer  (bounded, max 10_000)
                        │
                        ▼
                   PostgreSQL  (bulk insert)
```

1. **Dispatch:** the redirect process hands raw request data to a task under
   `Qwynk.TaskSupervisor` and returns immediately.
2. **Enrichment (in the task):** geo from the local mmdb; `visitor_hash =
   SHA256(ip <> user_agent <> daily_salt)`; referrer reduced to its host;
   device classified from the UA. The salt comes from `:persistent_term`,
   never from PostgreSQL — the redirect path must not depend on the DB for hashing.
3. **Buffer:** only the anonymous struct is cast to the GenServer.
4. **Flush:** every 5 seconds OR at 1000 items → `Ash.bulk_create/3`.
5. **Backpressure:** at 10_000 buffered events, new events are **dropped** and
   counted via telemetry. If PostgreSQL is down, the buffer retries on the next
   tick until the bound is reached, then sheds. Redirects never block or fail
   because analytics is unhealthy.
````

- [ ] **Step 5: Write the resource**

```elixir
defmodule Qwynk.Traffic.Link do
  use Ash.Resource,
    otp_app: :qwynk,
    domain: Qwynk.Traffic,
    data_layer: AshPostgres.DataLayer,
    authorizers: [Ash.Policy.Authorizer]

  postgres do
    table "links"
    repo Qwynk.Repo
  end

  actions do
    defaults [:read]

    create :create do
      primary? true
      accept [:destination, :slug, :strategy]
      change relate_actor(:owner)
      change Qwynk.Traffic.Changes.EnsureSlug
    end

    read :resolve do
      get? true
      argument :slug, :string, allow_nil?: false
      filter expr(slug == ^arg(:slug) and is_active == true)
    end

    update :update do
      primary? true
      accept [:destination, :strategy, :is_active]
      require_atomic? false
    end

    update :disable do
      accept []
      require_atomic? false
      change set_attribute(:is_active, false)
    end

    destroy :destroy do
      primary? true
      require_atomic? false
    end
  end

  policies do
    policy action(:resolve) do
      authorize_if always()
    end

    policy always() do
      authorize_if relates_to_actor_via(:owner)
    end
  end

  attributes do
    uuid_primary_key :id

    attribute :slug, :string do
      allow_nil? false
      public? true
      constraints min_length: 3, max_length: 64, match: ~r/^[a-z0-9-]+$/
    end

    attribute :destination, :string, allow_nil?: false, public?: true

    attribute :strategy, :atom do
      public? true
      default :temporary
      constraints one_of: [:permanent, :temporary]
    end

    attribute :is_active, :boolean, allow_nil?: false, default: true, public?: true

    create_timestamp :inserted_at
    update_timestamp :updated_at
  end

  relationships do
    belongs_to :owner, Qwynk.Accounts.User, allow_nil?: false, public?: true
  end

  identities do
    identity :unique_slug, [:slug]
  end
end
```

`:resolve` is `authorize_if always()` deliberately: a public redirect has no actor. Every other action is owner-scoped.

- [ ] **Step 6: Write the domain with bounded retry**

```elixir
defmodule Qwynk.Traffic do
  use Ash.Domain, otp_app: :qwynk

  alias Qwynk.Traffic.{Link, SlugGenerator}

  resources do
    resource Link do
      define :get_link, action: :read, get_by: [:id]
      define :list_links, action: :read
      define :resolve, action: :resolve, args: [:slug]
      define :insert_link, action: :create
      define :update_link, action: :update
      define :disable_link, action: :disable
    end
  end

  # 774_400 possible slugs means birthday collisions start biting near ~1k links.
  # Five fresh draws, then a numeric suffix that cannot realistically collide.
  @attempts 5

  def create_link(attrs, opts \\ []), do: do_create(attrs, opts, @attempts)

  defp do_create(attrs, opts, 0) do
    attrs |> Map.put(:slug, SlugGenerator.generate_with_suffix()) |> insert_link(opts)
  end

  defp do_create(attrs, opts, attempts) do
    case insert_link(attrs, opts) do
      {:error, error} ->
        if Map.has_key?(attrs, :slug) or not slug_taken?(error) do
          {:error, error}
        else
          do_create(attrs, opts, attempts - 1)
        end

      ok ->
        ok
    end
  end

  defp slug_taken?(%Ash.Error.Invalid{errors: errors}) do
```

```elixir
defmodule Qwynk.Traffic.Cache do
  @moduledoc """
  Read-through ETS cache for the redirect hot path.

  The stored entry carries `link_id` so the analytics path never needs a second
  lookup. TTL is a safety net only — mutations invalidate explicitly via
  `Qwynk.Traffic.Changes.InvalidateCache`.
  """

  @table :qwynk_cache
  @ttl_ms :timer.minutes(10)

  def init do
    :ets.new(@table, [:named_table, :set, :public, read_concurrency: true])
  rescue
    ArgumentError -> @table
  end

  def entry(link), do: %{link_id: link.id, destination: link.destination, strategy: link.strategy}

  def fetch(slug) do
    now = System.monotonic_time(:millisecond)

    case :ets.lookup(@table, slug) do
      [{^slug, entry, expires_at}] when expires_at > now -> {:hit, entry}
      [{^slug, _, _}] -> delete(slug); :miss
      [] -> :miss
    end
  end

  def put(slug, entry, ttl_ms \\ @ttl_ms) do
    :ets.insert(@table, {slug, entry, System.monotonic_time(:millisecond) + ttl_ms})
    entry
  end

  def delete(slug), do: :ets.delete(@table, slug)
end
```

The `rescue ArgumentError` makes `init/0` idempotent so tests can call it repeatedly. `:public` is required: the request process writes on a miss.

```elixir
defmodule Qwynk.Analytics.Salt do
  @moduledoc """
  Today's hashing salt, held in `:persistent_term`.

  PostgreSQL must never be on the redirect path, and hashing must keep working
  when the DB is down — so the salt is read at most once a day and cached.
  """

  @key {__MODULE__, :salt}

  def current do
    today = Date.utc_today()

    case :persistent_term.get(@key, nil) do
      {^today, secret} -> secret
      _ -> load(today)
    end
  end

  def refresh, do: current()

  defp load(today) do
    secret =
      Qwynk.Analytics.DailySalt
      |> Ash.Changeset.for_create(:get_or_create_today, %{date: today})
      |> Ash.create!(authorize?: false)
      |> Map.fetch!(:secret)

    :persistent_term.put(@key, {today, secret})
    secret
  end
end
```

```elixir
defmodule Qwynk.Analytics.Enrich do
  @moduledoc """
  The privacy boundary. Raw IP and User-Agent enter here and do not leave.

  Everything downstream — the buffer, the database, the admin — sees only the
  anonymous event this returns. Run this before buffering, never inside it.
  """

  alias Qwynk.Analytics.{Geo, Salt}

  @bot ~r/bot|crawler|spider|crawling|curl|wget|headless/i
  @tablet ~r/ipad|tablet|playbook|silk|(android(?!.*mobile))/i
  @mobile ~r/mobile|iphone|ipod|android|blackberry|opera mini|iemobile/i

  def call(%{link_id: link_id, ip: ip, user_agent: ua, referrer: referrer}) do
    %{
      link_id: link_id,
      timestamp: DateTime.utc_now() |> DateTime.truncate(:second),
      visitor_hash: hash(ip, ua),
      country: Geo.country(ip),
      device: device(ua),
      referrer_domain: referrer_domain(referrer)
    }
  end

  defp hash(ip, ua) do
    :crypto.hash(:sha256, [to_string(ip), to_string(ua), Salt.current()])
    |> Base.encode16(case: :lower)
  end

  defp device(nil), do: :desktop

  defp device(ua) do
    cond do
      Regex.match?(@bot, ua) -> :bot
      Regex.match?(@tablet, ua) -> :tablet
      Regex.match?(@mobile, ua) -> :mobile
      true -> :desktop
    end
  end

  # Host only. Never the path, query string, or fragment — those carry secrets.
  defp referrer_domain(nil), do: nil

  defp referrer_domain(referrer) do
    case URI.parse(referrer) do
      %URI{host: host} when is_binary(host) and host != "" -> host
      _ -> nil
    end
  end
end
```

- [ ] **Step 2: Implement `stats/2` as one SQL query.** Ash aggregates do not express `count(distinct …)` grouped by day without contortion:

```elixir
  # ponytail: raw SQL for the daily group-by; Ash aggregates can't express
  # count(distinct visitor_hash) per day without a custom fragment. Move it to
  # an Ash calculation if this query ever needs policy filtering.
  def stats(link_id, days \\ 30) do
    since = Date.add(Date.utc_today(), -(days - 1))

    %{rows: rows} =
      Qwynk.Repo.query!(
        """
        select d::date,
               count(h.id),
               count(distinct h.visitor_hash)
          from generate_series($2::date, current_date, '1 day') d
          left join hits h
            on h.link_id = $1 and h.timestamp::date = d::date
         group by d order by d
        """,
        [Ecto.UUID.dump!(link_id), since]
      )

    Enum.map(rows, fn [date, clicks, uniques] ->
      %{date: date, clicks: clicks, uniques: uniques}
    end)
  end
```

`generate_series` does the zero-filling in the database, so no gap-filling code is needed in Elixir.
